3.5.2. Документация по работе с веб-приложением

Веб-приложение реализовано на фреймворке Django 5.x и функционирует как клиент к REST API FastAPI. Django не хранит доменные данные в своей базе: все операции чтения и записи выполняются через модуль app/services/api_client.py, который отправляет HTTP-запросы к API версии v2 (базовый адрес задаётся переменной API_BASE_URL, по умолчанию http://127.0.0.1:8000/api/v2).

После успешного входа в сессии Django сохраняются:
  • access_token — JWT-токен для заголовка Authorization при запросах к API;
  • token_type — обычно bearer;
  • role_name — имя роли (admin, manager, user), извлекается из токена;
  • user_info — данные профиля с эндпоинта GET /api/v2/auth/me.

При ответе API со статусом 401 (истёкший или недействительный токен) сессия сбрасывается, пользователю выводится сообщение об ошибке и выполняется перенаправление на страницу входа. Уведомления об успешных операциях и ошибках отображаются через стандартный механизм django.contrib.messages (всплывающие блоки в шаблоне partials/messages.html). Тексты ошибок API сокращаются функцией format_api_detail() до понятных фраз на русском языке (некорректный email, короткий пароль и т.д.).

Базовый URL веб-приложения (локально): http://127.0.0.1:8001/

Общие элементы интерфейса

Шапка сайта (навигационная панель) отображается на всех страницах и содержит:
  • логотип/название «АРМ Застройщика» со ссылкой на главную (GET /);
  • пункт «Каталог» — доступен всем посетителям;
  • для авторизованных пользователей: «Кабинет»;
  • для ролей manager и admin: «Объекты CRM», «Менеджер», «Договоры»;
  • для роли admin дополнительно: «Пользователи»;
  • справа — email текущего пользователя и роль, кнопки «Войти» / «Регистрация» или «Выйти».

Оформление выполнено с использованием Bootstrap 5 и кастомных стилей (web_client_django/static/css/style.css). Карточки объектов, таблицы и формы имеют единый визуальный стиль.

2. Авторизация и регистрация

2.1. Вход в систему

GET /login/ — отображение формы входа (поля: email, пароль). Ссылка на регистрацию и напоминание о смене пароля в профиле.

При отправке формы (POST /login/) Django вызывает ApiClient.login(), который отправляет на FastAPI запрос POST /api/v2/auth/login (form-data: username=email, password). При успехе:
  • токен и роль сохраняются в session;
  • загружается профиль через GET /api/v2/auth/me;
  • выводится сообщение «Вход выполнен»;
  • выполняется redirect на /catalog/ (единая точка входа для всех ролей).

При неверных данных пользователь остаётся на странице входа, вверху отображается краткое сообщение об ошибке (например, «Неверный email или пароль»), без технических деталей JSON.

Рисунок 4 — Форма авторизации

2.2. Регистрация

GET /register/ — форма с полями email и пароль (минимум 6 символов, проверка на стороне Django-формы RegisterForm).

POST /register/ — вызов POST /api/v2/auth/register. При успехе — сообщение «Пользователь создан. Теперь можно войти.» и redirect на /login/. При занятом email — сообщение об ошибке из API.

Рисунок 5 — Форма регистрации

2.3. Выход

GET /logout/ (ссылка «Выйти» в шапке) — вызов POST /api/v2/auth/logout (если токен есть), очистка session (flush), сообщение «Вы вышли из аккаунта», redirect на /login/.

2.4. Восстановление пароля

GET /forgot-password/ — информационная страница: автоматическое восстановление по email в проекте не реализовано; смена пароля выполняется в разделе профиля после входа.


3. Каталог объектов недвижимости (все пользователи, в том числе гости)

GET /catalog/ — основной раздел просмотра объектов. Данные загружаются запросом GET /api/v2/properties с параметрами фильтрации и пагинации.

Элементы страницы:
  • форма фильтров PropertyFilterForm: тип объекта (выпадающий список из GET /api/v2/property-types), статус, диапазон цены (min/max), диапазон площади (min/max);
  • кнопка применения фильтров (отправка GET-запроса с query-параметрами);
  • сетка карточек объектов: адрес, тип, площадь, этаж, цена, скидочная цена (если есть), статус, обложка (первое фото объекта из общего списка фото API);
  • блок пагинации (page, size; по умолчанию size=12).

Нажатие на карточку или ссылку «Подробнее» открывает карточку объекта.

4. Карточка объекта недвижимости

GET /properties/{property_id}/ — детальная информация об объекте.

Отображаемые данные (из GET /api/v2/properties/{id}):
  • тип объекта, адрес, площадь, этаж / этажность, отделка, материал стен;
  • основная и скидочная цена;
  • статус («в продаже», «продан», «забронирован»);
  • текстовое описание.

Галерея фотографий — GET /api/v2/photos/{property_id}; изображения подгружаются с сервера FastAPI (каталог uploads/, URL через media_urls).

Список строительной документации — GET /api/v2/documents/{property_id}; для каждого файла указаны имя, тип документа (схема, план застройки), ссылка на скачивание.

Для авторизованного пользователя с ролью user доступна кнопка «Забронировать» (POST /properties/{id}/reserve/) — вызывает API POST /api/v2/properties/{id}/reserve; при успехе статус меняется на «забронирован»; при конфликте (объект уже продан/забронирован) выводится сообщение об ошибке.

Для ролей manager и admin на этой же странице доступны формы управления медиа (POST с полем action):
  • upload_photo, update_photo, delete_photo — работа с фотографиями;
  • upload_document, update_document, delete_document — работа с документами (тип doc_type обязателен).

Просмотренные объекты сохраняются в session (view_history) для отображения в личном кабинете.

3.5.3. Руководство по развёртыванию проекта

В данном разделе приведена пошаговая инструкция развёртывания информационной системы «АРМ застройщика» на локальном компьютере под управлением ОС Windows (аналогичные шаги применимы для Linux/macOS с заменой путей активации venv).

Требования к программному обеспечению:
  • Python 3.10 или выше;
  • PostgreSQL 14+ (рекомендуется 17+);
  • Git (опционально, для клонирования репозитория);
  • браузер Google Chrome, Mozilla Firefox или Microsoft Edge (для работы и E2E-тестов);
  • два свободных TCP-порта: 8000 (FastAPI) и 8001 (Django).

Шаг 1. Установка PostgreSQL и создание базы данных

1.1. Скачайте дистрибутив PostgreSQL с официального сайта https://www.postgresql.org/download/ и выполните установку.
1.2. Запомните пароль суперпользователя postgres.
1.3. Создайте базу данных для проекта (через pgAdmin или psql):

CREATE DATABASE tverdov_api_db;

Рисунок 21 — Создание базы данных в pgAdmin (при необходимости вставить скриншот)


Шаг 2. Подготовка репозитория проекта

2.1. Распакуйте архив курсового проекта или выполните git clone <url> в выбранную папку.
2.2. Корневая директория проекта: tverdov_kursovya (содержит папки app, web_client_django, tests).


Шаг 3. Запуск FastAPI (API-бэкенд)

FastAPI необходимо запустить первым, так как Django обращается к его эндпоинтам.

3.1. Откройте терминал и перейдите в корень проекта:
cd tverdov_kursovya

3.2. Создайте и активируйте виртуальное окружение:
python -m venv .venv
.venv\Scripts\activate

3.3. Установите зависимости:
pip install -r requirements.txt

3.4. Создайте файл app/.env (на основе существующего примера или вручную):

DATABASE_URL=postgresql+psycopg2://postgres:ВАШ_ПАРОЛЬ@localhost:5432/tverdov_api_db
SECRET_KEY=случайная_длинная_строка_для_JWT
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30

3.5. Запустите сервер FastAPI:
uvicorn app.main:app_v1 --reload --host 127.0.0.1 --port 8000

3.6. При первом запуске выполняется init_db(): создание таблиц, начальные роли (admin, manager, user) и типы недвижимости.

3.7. Проверьте доступность документации API:
  • Swagger UI v1: http://127.0.0.1:8000/api/v1/docs
  • Swagger UI v2: http://127.0.0.1:8000/api/v2/docs
  • раздача загруженных файлов: http://127.0.0.1:8000/uploads/

Рисунок 22 — Swagger UI API v2 (при необходимости вставить скриншот)


Шаг 4. Запуск Django (веб-интерфейс)

4.1. Откройте второй терминал (FastAPI должен продолжать работать в первом).

4.2. Перейдите в каталог клиента:
cd web_client_django

4.3. Создайте виртуальное окружение и установите зависимости:
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

4.4. Скопируйте конфигурацию окружения:
copy .env.example .env

4.5. Отредактируйте web_client_django/.env:

DJANGO_SECRET_KEY=ваш-секрет-django
DJANGO_DEBUG=1
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost
API_BASE_URL=http://127.0.0.1:8000/api/v2
API_TIMEOUT_SECONDS=20

Важно: API_BASE_URL должен указывать на порт 8000 (FastAPI), а не 8001.

4.6. Примените миграции Django (служебные таблицы сессий и админки Django):
python manage.py migrate

4.7. Запустите веб-сервер на порту 8001:
python manage.py runserver 8001

4.8. Откройте в браузере: http://127.0.0.1:8001/


Шаг 5. Проверка работоспособности

5.1. Убедитесь, что оба процесса запущены без ошибок (терминалы FastAPI и Django).
5.2. Откройте http://127.0.0.1:8001/catalog/ — должен отобразиться каталог (возможно пустой до добавления объектов).
5.3. Выполните вход под учётной записью admin@example.com / password123 (или зарегистрируйте нового пользователя).
5.4. Проверьте разделы «Объекты CRM», «Менеджер», «Кабинет» в зависимости от роли.
5.5. Создайте тестовый объект, загрузите фото, смените статус, сформируйте договор и скачайайте .docx.
5.6. (Опционально) Запустите автотесты из корня проекта:
pytest tests/api
pytest tests/e2e -m e2e


Примечания по эксплуатации

  • При ответе API 401 Django сбрасывает сессию и перенаправляет на /login/.
  • Остановка серверов: Ctrl+C в каждом терминале.
  • Каталог uploads/ должен быть доступен на запись для загрузки фото и документов.
  • При смене хоста или порта FastAPI обновите API_BASE_URL в .env Django.

  • REST API FastAPI (версии v1 и v2): аутентификация, CRUD объектов недвижимости, типы, фото, документы, договоры;
  • веб-приложение Django: сценарии гостя, пользователя (user), менеджера (manager), администратора (admin);
  • интеграция Django ↔ FastAPI через JWT и API v2;
  • автоматизированные тесты pytest (API) и Selenium (E2E).

Результаты автоматизированного тестирования:
  • tests/api/ — 86 тестов, все пройдены успешно;
  • tests/e2e/ — 25 E2E-тестов (каталог, вход, регистрация, navbar, logout и др.), все пройдены при запущенных сервисах на портах 8000 и 8001.

Итого: 111 автоматизированных тест-кейсов. Критических и блокирующих дефектов на момент сдачи проекта не выявлено.

В ходе промежуточного тестирования API v1 были зафиксированы дефекты (HTTP-статусы, валидация цен), устранённые в версии API v2; корректность исправлений подтверждена регрессионными тестами test_property_types_v2.py и смежными модулями.

Система рекомендована к опытной эксплуатации в учебной и демонстрационной среде.

ЗАКЛЮЧЕНИЕ

В ходе выполнения курсового проекта разработана и протестирована информационная система «АРМ застройщика», предназначенная для автоматизации учёта объектов недвижимости, управления фотографиями и строительной документацией, ведения статусов продаж и оформления договоров купли-продажи.

В рамках проекта созданы два взаимосвязанных приложения: REST API на FastAPI (версии v1 и v2) с хранением данных в PostgreSQL и веб-клиент на Django, использующий API v2 для всех операций с данными. Реализована ролевая модель доступа (admin, manager, user) и сценарии для неавторизованных посетителей (просмотр каталога).

Реализованы ключевые функции: регистрация и JWT-аутентификация (Argon2), CRUD объектов и справочника типов, загрузка фото и документов, смена статусов и бронирование, генерация договоров в формате Word (.docx), администрирование пользователей. Для API предусмотрена автоматическая документация Swagger (offline).

Тестирование включало 86 API-тестов и 25 E2E-тестов на Selenium; все прогоны завершены успешно. Дефекты промежуточных версий устранены в API v2.

Разработанная система соответствует техническому заданию и может быть рекомендована к опытной эксплуатации и дальнейшему развитию (мобильный клиент, расширенная отчётность, интеграция с внешними CRM).

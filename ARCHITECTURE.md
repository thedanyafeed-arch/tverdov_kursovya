## 2.3. Архитектура приложения

Приложение следует модульной архитектуре с четким разделением на слои:

**Структура приложения:**

- **Слой представления (Presentation Layer)** - API маршруты в `app/api/v1/`;

- **Слой бизнес-логики (Business Logic Layer)** - контроллеры в `app/controllers/`;

- **Слой доступа к данным (Data Access Layer)** - модели и сессии в `app/models/` и `app/db/`;

- **Слой безопасности (Security Layer)** - аутентификация в `app/core/`;

**Модели данных:**

- **Role (Роль)** - идентификатор, название (admin, manager, user), описание;

- **User (Пользователь)** - идентификатор, email, хешированный пароль, статус активности, дата создания, ссылка на роль;

- **PropertyType (Тип недвижимости)** - идентификатор, название (квартира, дом, коммерческая недвижимость);

- **RealEstateObject (Объект недвижимости)** - идентификатор, ссылка на тип недвижимости, общая площадь, отделка, материал стен, этаж, общее количество этажей, цена, скидочная цена, статус (в продаже/продан/забронирован), адрес, описание, даты создания и обновления;

- **Photo (Фотография)** - идентификатор, ссылка на объект недвижимости, путь к файлу, имя файла, дата загрузки;

- **Document (Документ)** - идентификатор, ссылка на объект недвижимости, путь к файлу, имя файла, тип документа (схема, план застройки и т.д.), дата загрузки;

- **Contract (Договор)** - идентификатор, ссылка на объект недвижимости, ссылка на покупателя (пользователя), ссылка на менеджера (пользователя), дата договора, статус (создан/подписан), путь к сгенерированному файлу, дата создания;

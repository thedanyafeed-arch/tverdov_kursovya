# UML Диаграммы проекта "АРМ Застройщика"

## Описание

Данный документ содержит UML диаграммы проекта REST API для автоматизированного рабочего места застройщика.

## Файл диаграмм

Все диаграммы находятся в файле `uml_diagram.puml` в формате PlantUML.

## Как просмотреть диаграммы

### Вариант 1: Онлайн редактор PlantUML
1. Откройте https://www.plantuml.com/plantuml/uml/
2. Скопируйте содержимое файла `uml_diagram.puml`
3. Вставьте в редактор
4. Диаграммы отобразятся автоматически

### Вариант 2: VS Code расширение
1. Установите расширение "PlantUML" для VS Code
2. Откройте файл `uml_diagram.puml`
3. Нажмите `Alt+D` для предпросмотра

### Вариант 3: Локальная установка PlantUML
```bash
# Установка через Homebrew (macOS)
brew install plantuml

# Генерация PNG изображений
plantuml uml_diagram.puml
```

## Содержимое диаграмм

### 1. Диаграмма классов (Class Diagram)
**Название:** `АРМ_Застройщика_Диаграмма_Классов`

**Описание:** 
Показывает структуру моделей данных, контроллеров, роутеров и их взаимосвязи.

**Основные компоненты:**
- **Модели данных:**
  - `User` - пользователи системы
  - `Role` - роли (admin, manager, user)
  - `PropertyType` - типы недвижимости
  - `RealEstateObject` - объекты недвижимости
  - `Photo` - фотографии объектов
  - `Document` - документы объектов
  - `Contract` - договоры купли-продажи

- **Контроллеры:**
  - `AuthController` - аутентификация и управление пользователями
  - `PropertyController` - управление объектами недвижимости
  - `PhotoController` - управление фотографиями
  - `DocumentController` - управление документами
  - `ContractController` - генерация и управление договорами

- **Роутеры:**
  - `AuthRouter` - эндпоинты аутентификации
  - `PropertyRouter` - эндпоинты объектов недвижимости
  - `PhotoRouter` - эндпоинты фотографий
  - `DocumentRouter` - эндпоинты документов
  - `ContractRouter` - эндпоинты договоров
  - `PropertyTypeRouter` - эндпоинты типов недвижимости

- **Системные компоненты:**
  - `Security` - безопасность (JWT, хеширование паролей, проверка ролей)
  - `Database` - инициализация БД и начальных данных
  - `Session` - управление сессиями БД

### 2. Диаграмма последовательности: Регистрация и вход
**Название:** `Регистрация_и_Вход`

**Описание:**
Показывает процесс регистрации нового пользователя и аутентификации существующего пользователя.

**Основные сценарии:**
- Регистрация с проверкой уникальности email
- Автоматическое назначение роли "user"
- Вход с проверкой пароля и генерацией JWT токена

### 3. Диаграмма последовательности: Создание объекта недвижимости
**Название:** `Создание_Объекта_Недвижимости`

**Описание:**
Показывает процесс создания объекта недвижимости менеджером или администратором.

**Основные шаги:**
- Проверка авторизации и роли (manager/admin)
- Валидация типа недвижимости
- Валидация статуса объекта
- Создание записи в базе данных

### 4. Диаграмма последовательности: Генерация договора
**Название:** `Генерация_Договора`

**Описание:**
Показывает процесс генерации договора купли-продажи для объекта недвижимости.

**Основные шаги:**
- Проверка авторизации пользователя
- Получение данных объекта недвижимости и пользователей
- Генерация Word документа (.docx)
- Сохранение файла на диск
- Создание записи договора в БД

### 5. Диаграмма компонентов (Архитектура системы)
**Название:** `Архитектура_Системы`

**Описание:**
Показывает архитектуру системы с разделением на слои:
- API Layer (роутеры)
- Controller Layer (бизнес-логика)
- Security Layer (безопасность)
- Database Layer (работа с БД)

## Связи между компонентами

### Связи моделей данных:
- `User` → `Role` (многие к одному)
- `RealEstateObject` → `PropertyType` (многие к одному)
- `RealEstateObject` → `Photo` (один ко многим)
- `RealEstateObject` → `Document` (один ко многим)
- `RealEstateObject` → `Contract` (один ко многим)
- `Contract` → `User` (две связи: покупатель и менеджер)

### Связи контроллеров с моделями:
- Каждый контроллер работает со своими моделями данных
- Контроллеры используют `Session` для доступа к БД

### Связи роутеров с контроллерами:
- Каждый роутер вызывает соответствующий контроллер
- Роутеры используют `Security` для проверки доступа

## Роли и права доступа

### Admin (Администратор):
- Полный доступ ко всем функциям
- Управление пользователями (назначение ролей, удаление)
- Управление типами недвижимости
- Все функции менеджера

### Manager (Менеджер):
- Создание, редактирование, удаление объектов недвижимости
- Управление фотографиями и документами
- Управление договорами (создание, редактирование, удаление)
- Изменение статусов объектов

### User (Пользователь):
- Просмотр объектов недвижимости
- Просмотр фотографий и документов
- Создание договоров для себя
- Просмотр своих договоров
- Бронирование объектов
- Обновление своего профиля

## Статусы объектов недвижимости

- **"в продаже"** - объект доступен для покупки
- **"продан"** - объект продан
- **"забронирован"** - объект забронирован пользователем

## Статусы договоров

- **"создан"** - договор создан, но не подписан
- **"подписан"** - договор подписан сторонами

## Технологический стек

- **FastAPI** - веб-фреймворк
- **SQLModel** - ORM для работы с БД
- **PostgreSQL** - база данных
- **JWT** - аутентификация
- **python-docx** - генерация Word документов
- **fastapi-pagination** - пагинация результатов

## Примечания

- Все диаграммы созданы в формате PlantUML
- Диаграммы можно редактировать в любом текстовом редакторе
- Для визуализации требуется PlantUML (онлайн или локально)
- Диаграммы отражают текущее состояние проекта на момент создания
